# 2026-10-08 바구니 몸체 화면상 후보 — 오프라인 영상 점검

## 목적·입력

ArUco ID5 마커 중심이 바구니 입구 중심이 아니라는 앞선 확인에 이어, 기존 정면 영상에서 **갈색 바구니 몸체의 화면상 상자**를 찾을 수 있는지 탐색했다. [오프라인 검사기](../../scripts/audit_basket_body_candidate.py)는 중앙 140×140 px ROI와 한 장면에서 탐색한 HSV 범위의 최대 연결 성분을 쓴다. 저장된 관절·영상은 기존 감사기로 SHA-256/표본 수를 검증한 뒤 읽었다. 로봇·카메라 설정·원본 자료는 변경하지 않았다.

합계 2,711장 중 2,641장(97.4%)에서 후보를 찾았다. 이는 거의 같은 배치·조명에서 **정지한 갈색 바구니를 다시 찾는 비율**이지 입구 검출 정확도가 아니다. B 투입 70장에는 후보가 없었고 첫 실패는 해당 기록 452번째 프레임이다. 실패 구간의 정면 영상을 직접 보면 병과 그리퍼가 바구니 몸체를 가린다. B 기록의 후보 중심 x 최대 393.5 px·폭 최소 35 px도 가림에 따른 부분 성분일 수 있어 목표로 쓸 수 없다.

현재 읽기 전용 정면 JPEG 1장(SHA-256 `e017a771df2fc953979dc37a629aaed3db9e7ace21c035987651ed8b2b750751`)에서는 회전된 갈색 바구니 몸체 후보 `(x=320,y=259,w=106,h=76)` px를 얻었다. 이전 세로 방향 중간값 약 72×104 px와 가로/세로 관계가 바뀌었다. 하지만 이는 현장 이동·회전이 섞인 단일 장면이고, 검출된 것은 **색 성분 외접 상자**다. 입구 안쪽 경계, 중심, 높이, yaw, 테두리 여유 또는 로봇 좌표의 독립 검증이 아니다. ID5는 같은 읽기 전용 상태에서 보였고 `basket_pose_authorized=false`, 약통 검출 0개였다.

## 판정·다음 단계

`EXPLORATORY ONLY`: 고정 ROI/HSV는 해당 배치·색·조명에 과적합될 수 있고, 사람/그리퍼/병 가림 때 실패한다. 다른 색 바구니·독립 배치의 정량 라벨이 없으므로 입구 중심·자세 알고리즘으로 승격하지 않는다. 코드 출력은 `basket_mouth_detected=false`, `basket_pose_authorized=false`, `robot_enabled=false`, `motion_authorized=false`다. 자동 이동·재생 `NOT_RUN`. 현장 작업 없이 가능한 다음 단계는 기존 영상에서 바구니 **입구 네 모서리**를 사람이 확인한 검증 세트를 만들고, 그 뒤 회전/가림/조명별 오차를 평가하는 것이다. 이슈 API `NOT_RUN`, 원격 push `NOT_PUSHED`.
