## 준비와 관찰기 적용

- 사용자가 C 한 병을 고정 출발 자리에 배치했다. Mac 8031 정면·사선에는 C 후보 한 개와 비어 있는 빨강 ID4가 보였고 ID0–6이 검출됐다. C 후보는 기존 pickup ROI 밖이므로 로봇 목표점으로 사용하지 않았다.
- 시작 전 Jetson LeLab 8000의 텔레옵·녹화·추론은 모두 inactive, Mac 8030의 세 카메라 캐시는 fresh, `robot_control=false`였다.
- 기존 Mac 8030 관찰기 PID 29751만 정상 종료한 뒤 새 라벨 코드로 재시작했다. 첫 detached 실행은 프로세스가 남지 않아 실패했고, foreground PTY 세션에서 동일 포트·동일 인자로 기동했다. 기동 직후 사선·손목 HTTP 503은 일시적이었고, 후속 상태에서 세 카메라 오류 null·수십 ms 이내, 8031 입력 복구를 확인했다. Jetson LeLab·USB·모터·토크·캘리브레이션은 변경하지 않았다.

## 현장 시도와 중단

- 사용자가 현장 안전·리더/팔로워 시작 자세·즉시 중단 준비를 확인하고 C 상공 비접촉 1회를 승인했다. 기존 LeLab 텔레옵은 사용자가 직접 시작했고 API에서도 active 및 세 카메라·관절 방송 fresh를 확인했다.
- 사용자는 C 상공 정지와 실제 손가락–병 공기 간격·C 위치 유지라고 보고했다. 읽기 전용 관찰기에서 `SOURCE_C_HOVER` 한 건을 Git 제외 `.local/fixed-slot-waypoints/20261008T064040_540546Z_5cbd3102/`에 저장했다. 3시야와 15개 관절 표본, 수신시각 간격 8.7/0.1/0.1 ms, 관절 최대 표준편차 0.0 rad였다. 저장본 자체는 `use_for_replay=false`, `motion_authorized=false`다.
- 이어 사용자가 C에서 빈 그리퍼를 위로 빼 빨강 ID4 상공으로 옮기는 **별도 비접촉 1회**를 승인했다. 하지만 최신 정면·사선에는 C가 그리퍼 사이에서 출발 위치 밖으로 들려 이동한 모습이 보였고, 사용자는 실제 C를 잡거나 이동했다고 확인했다. 승인된 빈 그리퍼 비접촉 범위와 다르므로 **`BASKET4_HOVER`는 저장하지 않았고**, 앞서 저장한 `SOURCE_C_HOVER`도 비접촉 의미·출발 위치 불변을 독립 검증할 수 없어 `REJECTED_FOR_USE`다. 원본은 삭제·수정하지 않는다.
- 사용자가 현장 안전 절차로 물체와 팔을 안정시키고 종료했다고 보고했으나 첫 서버 재조회는 텔레옵 active였다. 재종료 요청 뒤 API `teleoperation_active=false`를 확인했다. 종료 영상에는 C가 작업대에 서 있고 그리퍼는 떨어져 보인다. 접촉·이동 원인은 이 기록만으로 특정하지 않는다.
