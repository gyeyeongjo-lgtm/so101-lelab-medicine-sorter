# 2026-10-08 8022 카메라 점유 정리와 캘리브레이션 한계 해석

## 승인·범위

사용자는 기존 8022 인스턴스 정리와 캘리브레이션 최대값 사용을 승인했다. 이번 작업에서는 로봇을 움직이거나 모터 목표·토크·캘리브레이션·설치 URDF·USB·웹캠 설정을 변경하지 않았다. 캘리브레이션 최대값은 **읽기 전용 범위 대조의 장치 상한**으로 취급한다. 자동 경로의 목표점 또는 충돌 없는 동작 범위로 승인하지 않는다.

## 실제 점유·사전 상태

Jetson의 `lelab-jetson-py310.service`는 PID 518961 아래 PID 518962로 포트 8022를 실행 중이었고, `lelab.service`는 PID 523353 아래 PID 523354로 포트 8000을 실행 중이었다. 8022의 텔레옵·녹화·추론과 8000의 텔레옵·녹화·추론은 모두 inactive였다. 8000 사선 `/camera-preview/4`는 HTTP 503, 8022의 같은 프리뷰는 HTTP 200이었다. 별도 `mediflow-capture-8011.service`는 실행 인자 `config/cameras.lelab8022.json`으로 8022 영상을 입력으로 사용 중이었다. 따라서 8022 중지는 8011의 영상 입력에도 영향을 준다.

## 한 변수 변경과 결과

승인된 정확한 `lelab-jetson-py310.service`만 `systemctl --user stop`으로 중지했고, 결과 `inactive/dead`, `MainPID=0`, `Result=success`, 8022 포트 listener 없음이었다. 8000은 재시작하지 않았다. 이후 8000의 정면 8·사선 4·손목 6 프리뷰 모두 HTTP 200으로 실제 영상 바이트를 전송했다. 무한 MJPEG 스트림을 3초에 끊은 curl timeout은 영상 수신 실패로 해석하지 않는다. 8000 `/health`는 `ok`, 텔레옵은 inactive였다.

Mac 8030 관찰기는 중지된 8022를 사선·손목 입력으로 가리켜 두 프레임 나이가 약 90초였다. 정확한 Mac PID 28891의 실행 인자를 확인하고 그 관찰기만 TERM 종료·포트 해제 후 같은 8000·저장 경로·8030 포트로, 대체 카메라 URL 없이 다시 시작했다. 재시작 뒤 두 차례 이상의 `/api/status`에서 정면·사선·손목의 프레임 나이는 각각 수십 ms 이하, 오류 null, `robot_control=false`였다. 8031 `/health`는 정면·사선 입력 `ok=true`, 프레임 나이 약 0.18/0.13초, `robot_enabled=false`였다. 현장은 빈 작업대라 약통 검출 0·바구니 마커 없음은 현 장면과 일치한다. 8011 서비스 설정은 변경하지 않았고, 8022 중지에 따른 8011 영상 기능은 `NOT_VERIFIED`다.

## 최대값과 다음 게이트

이전 승인된 읽기 전용 장치 점검에서 follower Elbow 위치 제한 raw 880–3087, Wrist_Pitch 936–3225가 설치 캘리브레이션 파일과 일치했다. 드라이버 변환상 양의 최대치는 약 +97.011°/+100.615°다. 앞선 수동 기록의 최대치는 약 +96.659°/+100.264°로 상한까지 각각 약 0.352°/0.351°뿐이다. 이 장치 상한은 **범위 초과 감지**에 쓰되 자동 목표·속도·경로의 안전 근거가 아니다. 설치 URDF의 +90°/+95°와 불일치도 그대로 보존한다. World→Base/TCP 및 연속 경로·여유 검증과 직전 한 관절 소폭 시험 실패가 남아 있어 자동 이동·재생·집기 `BLOCKED/NOT_RUN`이다.

8022 서비스는 `enabled` 상태여서 재부팅 후 다시 시작될 수 있다. 영구 비활성화는 이번 승인 범위에서 수행하지 않았다. GitHub 이슈 갱신 `NOT_RUN`, 원격 push `NOT_PUSHED`. 비밀번호·원본 영상·로그·데이터셋은 문서와 Git에 포함하지 않았다.
