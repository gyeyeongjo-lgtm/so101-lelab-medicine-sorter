대상은 Git 제외 `.local/teleop-traces/20261007T134310_742830Z_d309ec55/`의 사용자 직접 텔레옵 관찰 원본이다. 관절 JSONL·정면/사선 JPEG를 읽기만 했고 로봇·USB·LeLab 설정·원본은 변경하지 않았다. 분석 뒤 LeLab 텔레옵 API는 `active=false`였다.

## 확인 결과

- 기존 `audit_teleop_trace.py`가 관절 SHA-256, 2,298개 수·시간 순서, 정면 492장·사선 493장의 index/JPEG 해시를 확인했다. 결과는 `URDF_LIMIT_MISMATCH`: 설치 URDF Elbow 상한 +1.5708 rad 초과 792/2,298개, 최대 초과 0.114689 rad; 다른 다섯 관절 초과 0개다. 물리 하드스톱 위반의 증거가 아니며 자동 재생 허가도 아니다.
- 초과는 연속 index 0–791, 기록 시작부터 약 41.322초까지였다. 0.01 rad 기준 첫 자세 이탈은 index 777, 40.601초였다. 따라서 초과 대부분은 초기 대기 자세에 있었지만 첫 이동 약 0.72초와도 겹친다. 이후 샘플에서 URDF 상한 초과는 검출되지 않았다. 마지막 Elbow 방송값은 약 0.628319 rad다.
- 검증 후 실행한 `summarize_teleop_activity.py`는 잠정 활동 구간 79.384초·관절 1,521개를 반환했다. 그 구간의 수신시각 기준 정면/사선 JPEG는 각 323장이다. 기록 마지막 144개 관절 방송은 7.412초간 여섯 값이 모두 정확히 같았고 마지막 정면 JPEG에는 C 약통 위 그리퍼가 보인다. 동일 방송값은 실제 무동작·공기 간격·충돌 여유의 독립 측정이 아니다.
- 관찰기는 120초 제한으로 `stop_reason=max_duration`에 도달했다. 사용자가 이후 비접촉 퇴피를 보고했어도 이 원본이 퇴피 전체를 포함한다고 볼 수 없다. 카메라 시간은 Mac 수신시각이며 센서 노출시각/관절 동기화가 아니다. 원본 `camera_evidence_complete=false`, `use_for_replay=false`, `robot_enabled=false`, `motion_authorized=false`를 유지하고 분석 판정도 `training_ready=false`다.
