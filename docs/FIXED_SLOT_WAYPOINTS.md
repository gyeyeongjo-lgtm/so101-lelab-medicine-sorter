## 현재 구현 범위

- Mac 8030의 `scripts/teach_capture_web.py`에 로봇 제어가 없는 별도 `POST /api/waypoint-capture`를 추가했다. 사용자가 **기존 LeLab 텔레옵을 직접 켜고**, 빈 약통 상태에서 자세를 멈춘 경우에만 최근 관절 방송 15개와 정면·사선 영상(손목은 신선할 때 보조)을 `.local/fixed-slot-waypoints/`에 저장한다. 원래 P1–P6 접촉 캡처는 별도 폴더/API로 남기되 기본 차단하며 웹 버튼도 비활성화했다. `--allow-touch-capture`는 별도 승인된 과거 실험에만 사용한다.
- 저장소 코드와 현재 Mac 8030의 허용 라벨은 기존 `PARK`, `SOURCE1_HOVER`, `TRANSFER_HOVER`, `BASKET4_HOVER`, `BASKET4_RELEASE`와 새 `SOURCE_A_HOVER`, `SOURCE_B_HOVER`, `SOURCE_C_HOVER`, `BASKET5_HOVER`, `BASKET6_HOVER`다. 새 출발·바구니 상공 라벨은 **비접촉 정지 관찰**용이다. 이름만으로 실제 높이·충돌 여유나 놓기 성공을 보증하지 않는다. 각 저장본의 `capture_kind=waypoint`, `contact=not claimed`, `use_for_robot_world_fit=false`, `use_for_replay=false`, `robot_enabled=false`, `motion_authorized=false`가 기본값이다. 원본 영상·관절값은 Git-ignore 로컬에만 둔다.
- 저장 API는 텔레옵 활성, 현장 장면·완전 정지 확인, 15개 신선·안정 관절 방송, 정면·사선 영상의 수신시각 근접을 요구한다. 이 조건은 **증거 품질 게이트**이지 안전한 이동 경로의 증명이 아니다. 카메라 노출시각 동기화도 아니다.
- 새 라벨을 추가한 코드에는 궤적 생성·보간·모터/토크/USB/serial 제어·LeLab 시작/정지·재생 API가 없다. 준비 당시에는 라이브 적용·캡처 `NOT_RUN`이었으나, 이후 Mac 8030 관찰기만 재시작하고 C 상공 한 건을 저장했다. 후속 실제 C 집기·이동 때문에 이 건은 비접촉 경유 자세로 채택하지 않는다. 자동 재생 `NOT_RUN`이다.

## 첫 현장 teach 전에 필요한 확인

1. 별도 현장 안전 확인과 명시적 텔레옵 승인. LeLab의 텔레옵·녹화·추론 중복 금지, canonical leader/follower 및 버스 단독 점유, 리더·팔로워 시작 자세, 사람의 이동 범위 이탈과 즉시 중단 방법을 확인한다. LeLab 시작 API의 소프트웨어 속도 제한을 가정하지 않는다.
2. 첫 시연은 약통 없는 슬롯과 **빈 빨강 바구니 ID4**만 사용한다. 작업대 ID0–3·바구니 ID4의 실제 위치와 카메라 시야를 확인한다. 고정된 슬롯/바구니가 움직였거나 다른 물체가 경로에 있으면 teach를 진행하지 않는다.
3. 사용자가 리더로 천천히 이동시키며 각 라벨의 후보 자세에서 완전히 멈추고, 정면·사선 영상과 장애물 여유를 현장에서 확인한 뒤 저장한다. 다른 손가락이나 하우징으로 X에 접촉시키지 않는다. 순서 자체가 안전 경로라는 뜻은 아니다.
4. 종료 뒤 텔레옵·녹화·추론 inactive와 저장본 무결성, 각 관절 안정성, 영상상 간섭·시야·실제 높이를 검수한다. 전체 연결 경로의 충돌 여유는 이 정지 사진만으로 입증할 수 없다. 사용하지 않은 독립 자세·실제 경로 검증이 별도로 필요하다.

## 단계별 진입 게이트

| 단계 | 허용 범위 | 아직 필요한 것 |
| --- | --- | --- |
| A. 코드·계획 | 단위 테스트, 저장 형식·UI 준비 | 새 라벨은 8030에 적용됨. C 상공 첫 캡처는 의미 검증 실패로 채택 거부 |
| B. 현 배치 비접촉 teach | 사용자 직접 저속 텔레옵으로 **정지 자세 증거** 저장 | 현 배치·카메라 확인, 새 현장 안전 확인·명시 승인 |
| C. 경로 검증 | 첫 이동 전 연결 구간의 충돌·높이·관절 한계·STOP 검토 | 정지 waypoint만으로는 통과 불가. 별도 승인과 단계별 실제 검증 필요 |
| D. 모형 집기 | 하강·그리퍼 개폐·들기·투입·실패 복구 | 빈 장면 경로 검증 후 별도 설계·승인. 현재 `NOT_RUN` |

ID5(초록), ID6(파랑)와 A/B/C 출발 슬롯의 **캡처 라벨**은 준비됐지만, 어떤 목적지도 자동 경로로 승인된 것은 아니다. 수동 투입 성공과 정지 자세는 연결 구간의 충돌 여유·반복성을 입증하지 못한다. YOLO/ArUco는 슬롯·바구니의 존재와 배치 변화를 감지하는 관찰 계층이며, 이 waypoint 자료를 자동 모터 명령으로 전환하지 않는다.
