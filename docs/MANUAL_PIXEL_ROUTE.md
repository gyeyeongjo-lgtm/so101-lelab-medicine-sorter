# 수동 위치 지정 → 분류 목적지 확인 (로봇 구동 없음)

시간이 촉박할 때 사용할 **판정 전용** 경로다. 사람이 정면 영상의 약통 중심을 찍고 A(큰 약통)·B(중간)·C(작은) 중 하나를 직접 확인한다. 기존 검출기는 약통 한 클래스만 찾으므로 크기별 신원을 자동 분류하지 않는다. 규칙은 A→파랑 ID6, B→초록 ID5, C→빨강 ID4다.

저장소의 `scripts/medicine_yolo_web.py` 페이지에는 같은 순간의 정면 JPEG·검출 상자·ArUco 상태를 함께 고정하는 **현재 프레임 고정** 버튼이 있다. 약통 중심 클릭 시 영상이 신선한지, ID0–3과 목표 바구니 마커가 검출됐는지, 클릭점이 약통 검출 상자 안에 있는지 검사한다. 같은 약통에 겹친 상자(IoU ≥ 0.5)는 중복 후보로 묶어 결과에 개수를 표시한다. 다른 물체가 겹친 것으로 보이면 `BLOCKED`다. 고정 후 10초가 지나면 다시 찍어야 한다. 고정·클릭만 하면 파일은 남지 않는다.

사진을 남기려면 실제 물체 종류를 사람이 확인하고 `A/B/C 선택 → 현재 프레임 고정 → 약통 중심 클릭 → 사진·라벨 로컬 저장`을 누른다. 화면에 `SAVED_FOR_REVIEW`가 떠야 저장 성공이다. 이 버튼은 서버를 `--allow-manual-capture --manual-capture-root .local/medicine-manual-captures`로 실행했을 때만 동작한다. 동일 프레임 원본 JPEG와 사람 확인 라벨·클릭점·SHA-256·판정 메타데이터는 Git 제외 로컬 폴더에만 남는다. 같은 프레임 중복 저장은 거부한다. 저장본은 `FOR_REVIEW` 후보이지 자동 학습 정답이나 로봇 실행 승인 자료가 아니다. `training_ready=false`, `robot_enabled=false`, `motion_authorized=false`다.

같은 검사를 저장된 비전 상태 JSON에 적용할 때는 `scripts/medicine_sort_dry_run.py --snapshot 상태.json --verified-label A --pixel X Y --frame-sequence N`을 사용한다. `--pixel`과 `--frame-sequence`는 **해당 JSON과 정확히 같은 프레임**에서 얻은 값이어야 한다. 다른 프레임·오래된 프레임·검출 밖 클릭은 거부한다.

결과에는 기존 픽업 ROI 안인지도 별도로 표시한다. ROI 밖이어도 목적지 제안은 가능하지만, 자동 집기 가능 판정은 아니다.

이 결과는 바구니 ID 제안일 뿐이다. 마커의 설정상 색과 실제 색이 여전히 맞는지 사람의 확인이 필요하고, 픽셀/평면 투영에는 약통 높이, 로봇 베이스·TCP 보정, 연속 경로 여유가 없다. 자동 집기·관절 재생·모터 명령에는 사용하지 않는다. 현장 시연이 필요하면 사용자가 기존 LeLab 텔레옵을 직접 수행하고, 별도로 관찰·저장·검수한다.

2026-10-07 Mac의 임시 `http://127.0.0.1:8031/`에서 저장 버튼을 포함한 새 화면을 실행했다. 입력은 기존 8030의 `/frame/ceiling.jpg`·`/frame/oblique.jpg` 캐시뿐이므로 Jetson 카메라 장치를 다시 열지 않는다. 정면/사선 프레임·마커·검출과 서버 저장 기능 활성화는 확인했다. **저장 버튼 도입 이전에 고정·클릭만 한 여러 장은 파일로 남지 않았다.** 임시 서버는 영구 서비스가 아니며, 8020 기존 서비스/설정을 변경하지 않았다.

후속 촬영 90장 중 사용자가 A를 B로 저장했다고 알린 연속 10장은 원본을 변경하지 않고 별도 Git 제외 폴더로 옮겨 B 후보에서 제외했다. 현재 보유 후보는 C 22장·B 35장·A 23장이다. 이 숫자는 저장/무결성 검수 결과이지 학습 준비나 분류 정확도가 아니다. 각 물체를 왼쪽·가운데·오른쪽 고유 위치에서 찍었으므로 화면 위치만으로 라벨을 맞힐 수 있는 편향이 있다. 자동 분류 검증에는 **종류마다 위치를 섞은 독립 촬영** 또는 배경을 제거한 물체 중심 비교와 별도 검증 자료가 필요하다. 로봇 제어는 계속 비활성이다.

## 고정 배치 + 명령별 목적지 (별도 dry-run)

사용자는 C 왼쪽·B 가운데·A 오른쪽 배치를 항상 유지할 예정이며, `A를 빨간색, B도 빨간색 박스`는 실제 목적지 변경이 아니라 **명령 형식 예시**라고 확인했다. 따라서 기존 기본 규칙은 변경하지 않았다. 새 `scripts/medicine_fixed_slot_command.py`는 한 클래스 YOLO 검출 상자의 가로 위치와 높이 가드를 `configs/medicine_fixed_slots.example.json`의 임시 640×480 슬롯 범위에 대조한다. 이름을 찾는 기능과 목적지를 정하는 기능은 분리돼, 한 명령에서 A·B 모두 빨강 ID4처럼 다대일 목적지도 허용한다. 예: `--snapshot 현재상태.json --command 'A를 빨간색, B도 빨간색 박스'`. 텍스트 형식이 불명확하거나, 요청한 약통/마커가 없거나, 한 슬롯에 중복 물체가 있거나, 박스 크기가 임시 범위를 벗어나면 `BLOCKED`다.

Mac 8031 화면의 `고정 배치 명령 미리보기`에서 같은 문장을 입력하고 `명령 판정만`을 누를 수도 있다. 화면의 현재 **신선한 정면 프레임**만 검사하며 명령을 저장·실행하지 않는다. 요청한 종류가 지금 보이지 않으면 `requested_bottle_missing`으로 차단한다. 따라서 A만 놓인 장면에서 `A를 빨강, B도 빨강`을 입력해도 B를 나중 작업으로 예약하지 않는다. 이는 명령 정책 저장 기능이 아니라 한 프레임의 판정 미리보기다.

보유 사진 80장에 기존 ONNX 검출을 다시 실행해 슬롯 판정은 C 22/22·B 35/35·A 23/23 통과했다. 이 오프라인 검사는 **마커 상태를 합성해 판정 함수에 입력**했으므로 현장 마커 검증이나 독립 성능평가가 아니다. Mac 8031의 A 단독 라이브 프레임에서는 `A를 빨간색`이 ID4로 `DRY_RUN_ROUTE_ONLY`를 반환했다. 이어 사용자가 세 약통을 동시에 고정 배치한 라이브 프레임에서는 약통 상자 3개·ID0–6이 검출됐고 기본 A→ID6/B→ID5/C→ID4 명령과 A·B→ID4 예시가 모두 `DRY_RUN_ROUTE_ONLY`로 판정됐다. 이는 사용자 배치 보고에 의존하는 한 현장 장면 시험이며 다른 날 조명/카메라 변화는 아직 검증하지 않았다. 결과에는 로봇 집기 좌표·경로·바구니 용량 검사가 없고 `robot_enabled=false`, `motion_authorized=false`다. 여러 약통을 같은 바구니에 실제 투입하려면 순서·용량·간섭을 별도로 검증해야 한다.

기존 80장 메타데이터의 픽업 ROI 일치는 A 0/23·B 35/35·C 0/22다. 라이브 세 병 프레임도 A/C는 ROI 밖, B만 안이다. 명령 결과의 `pickup_roi_match`는 이 평면상 중심 판정을 표시할 뿐이며, `grasp_authorized`는 항상 false다. B가 ROI 안이어도 손끝 위치·약통 높이·World→Base/TCP 보정·연속 경로는 검증되지 않았다. A/C를 포함하려고 ROI만 넓히거나, 이 미리보기 결과로 자동 집기를 시작하지 않는다. 실제 로봇 동작은 별도 안전 확인과 해당 시험의 승인이 필요하다.
